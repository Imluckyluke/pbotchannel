# ربات رله (ربات اصلی + سشن‌بات)

سیستم از فقط **دو تا کلاینت تلگرام** تشکیل شده:
- **ربات اصلی**: توکن از BotFather، پنل مدیریت رو نشون میده و فایل‌ها رو ازت میگیره.
- **سشن‌بات (یوزربات)**: با اکانت شخصی لاگین میشه، عضو کانال‌های مبدا میشه، با
  «ربات اول» و «ربات دوم» گفتگو میکنه و پست نهایی رو توی کانال‌های مقصد میذاره.

## نصب لوکال (اختیاری)
```bash
pip install -r requirements.txt
cp .env.example .env
python bot.py
```
دیگه لازم نیست از `generate_session.py` استفاده کنی؛ لاگین سشن کاملاً از
داخل خود ربات با کلید شیشه‌ای انجام میشه (پایین‌تر توضیح داده شده).
`generate_session.py` فقط به عنوان یه راه جایگزین/دستی نگه داشته شده.

## دیپلوی روی Railway
1. یه پروژه‌ی جدید بساز و این ریپازیتوری/فولدر رو بهش وصل کن (یا از طریق
   Railway CLI آپلود کن). ریلوی با وجود `Procfile` و `requirements.txt`
   خودش تشخیص میده و به عنوان یه **Worker** اجراش میکنه (نه Web Service،
   پس نیازی به پورت نیست).
2. توی تب **Variables** این متغیرها رو بذار:
   - `API_ID`
   - `API_HASH`
   - `BOT_TOKEN`
   - `ADMIN_IDS`
   - `DB_PATH` = `/data/data.sqlite3`
3. یه **Volume** بساز و به مسیر `/data` مونت کن (Settings → Volumes).
   این خیلی مهمه: بدون Volume، سر هر ری‌دیپلوی سشن و تنظیماتی که از پنل
   وارد کردی پاک میشه و باید دوباره لاگین کنی.
4. Deploy بزن. توی لاگ باید ببینی `bot started`.
5. برو تو ربات اصلی‌ات، `/panel` رو بزن و طبق بخش زیر لاگین کن.

## لاگین سشن از داخل ربات (بدون نیاز به سرور جدا)
از پنل (`/panel`) دو راه برای وارد کردن سشن هست:

**۱. ورود با شماره** (روی **🔑 ورود با شماره** بزن):
1. شماره تلفن اکانت سشن رو با فرمت بین‌المللی بفرست (مثلا `+989123456789`).
2. کدی که تلگرام میفرسته رو با **کلیدهای شیشه‌ای** (۰ تا ۹، ⌫، ✅ تایید)
   وارد کن — نیازی به تایپ نیست.
3. اگه اکانت تایید دو مرحله‌ای (2FA) داشته باشه، ربات خودش تشخیص میده و
   ازت میخواد رمز رو به صورت پیام متنی بفرستی؛ بلافاصله بعد از خوندن،
   پیام حاوی رمز حذف میشه.
4. بعد از موفقیت، استرینگ سشن داخل دیتابیس ذخیره میشه، کلاینت سشن همون
   لحظه وصل میشه (دیگه لازم نیست ری‌استارت کنی)، و خودِ Session String هم
   توی پیام تاییدیه بهت نشون داده میشه که برای دفعات بعد نگهش داری.

**۲. ورود مستقیم با Session String** (روی **📋 ورود مستقیم با Session
String** بزن): اگه از قبل یه Session String داری (مثلاً از همون پیام
تاییدیه‌ی بالا، یا از `generate_session.py`)، کافیه بفرستیش؛ ربات باهاش
وصل میشه و ذخیره‌اش میکنه، بدون نیاز به شماره و کد.

⚠️ Session String معادل دسترسی کامل به همون اکانت تلگرامه؛ جایی نگهش دار
که فقط خودت بهش دسترسی داری.

## پنل تنظیمات (`/panel` یا `/start`)
- 🤖 ربات اول (قبلاً «ربات X»)
- 🤖 ربات دوم (قبلاً «ربات بکاپ»)
- 🔗 کلمه‌ی تبدیل به لینک
- 🔑 ورود با شماره / 📋 Session String
- 📢 کانال‌های مقصد (جایی که پست نهایی گذاشته میشه؛ هر کانال رو میشه از
  همینجا فعال/غیرفعال کرد بدون اینکه حذفش کنی)
- 📡 کانال‌های مبدا - مانیتور (جایی که ازش فایل جدید گرفته میشه)
- ⏱ فاصله زمانی بین هر پست (دقیقه)
- 🔢 تعداد پست روزانه
- 📝 قالب جایگزین (وقتی پست کانال مبدا کپشن نداره)
- 👤 مدیریت ادمین‌ها (افزودن/حذف)
- ℹ️ نمایش کامل تنظیمات

روی هر گزینه بزنی، مقدار فعلیش رو نشون میده و ازت میخواد مقدار جدید رو
به صورت پیام بفرستی؛ همون لحظه ذخیره میشه و برمیگرده به منوی اصلی.
هیچ دستور متنی‌ای لازم نیست، همه چیز کلیدیه.

پیش‌فرض دکمه‌های ربات دوم همون متن‌هایی هست که گفتی (آپلود فایل / تکی /
بازگشت به منو اصلی)؛ اگه دقیقاً همونا باشه نیازی به تغییر نیست.

## استفاده — حالت دستی
1. فایل رو برای ربات اصلی بفرست.
2. ربات فایل رو میده به ربات اول، لینک میگیره، بعد میره تو ربات دوم
   (/admin → دکمه آپلود فایل → دکمه تکی → فرستادن لینک → گرفتن لینک نهایی →
   دکمه بازگشت به منو اصلی) و لینک نهایی رو برات میفرسته.
3. حالا کپشن نهایی رو با همون فرمتی که میخوای بفرست، مثلاً:
```
سلام امروز اومدیم با...

مشاهده

ایدی کانال
```
   ربات کلمه‌ی «مشاهده» رو به لینک نهایی هایپرلینک میکنه و «ایدی کانال» رو با
   نام کانال مقصد جایگزین میکنه و پیام رو مستقیم توی کانال مقصد پست میکنه.
   (توی حالت خودکار که کپشن از کانال مبدا کپی میشه و اون literal «ایدی کانال»
   رو نداره، بجاش آخرین `@یوزرنیم`ِ توی متن — که معمولاً برچسبِ خودِ کانال
   مبداست — با آیدیِ کانال مقصد جایگزین میشه؛ پایین‌تر توضیح داده شده.)

## استفاده — حالت خودکار (مانیتور کانال مبدا)
1. از پنل، روی «📡 کانال‌های مبدا - مانیتور» بزن و لینک/یوزرنیم/آیدی
   کانال مبدا رو اضافه کن (سشن باید از قبل لاگین باشه تا بتونه عضو بشه).
2. یه پروسه‌ی پس‌زمینه هر «فاصله زمانی بین هر پست» دقیقه یک‌بار، آخرین
   پیام هر کانال مبدا رو چک می‌کنه. اکثر پست‌های کانال مبدا خودشون فایل
   ندارن، فقط یه متن با یه **دیپ‌لینک** زیرشون هستن (مثلا کلمه‌ی «مشاهده»
   هایپرلینک شده به `t.me/یه_ربات?start=...`) — دقیقا همون فرمتی که خود
   این ربات هم موقع پست کردن تولید می‌کنه. برای این حالت:
   - ربات دیپ‌لینک رو باز می‌کنه (`/start` با پارامترش رو به همون ربات
     مقصد می‌فرسته).
   - اگه اون ربات به‌جای فایل، خواست عضو یه یا چند کانال بشیم (گیت
     اجباری)، خودش از روی دکمه‌های زیر پیام، کانال‌ها رو پیدا و عضو
     می‌شه، بعد دکمه‌ی «تایید عضویت» رو می‌زنه (یا اگه چنین دکمه‌ای
     نبود، دوباره `/start` می‌فرسته) و این حلقه رو تا ۴ بار تکرار
     می‌کنه تا فایل واقعی برسه.
   - اگه پست کانال مبدا به‌جای دیپ‌لینک، خودش مستقیم فایل/عکس چسبیده
     داشته باشه (حالت قدیمی‌تر)، همون‌جوری مستقیم استفاده میشه.
   **هیچ‌جای این مسیر فایل روی سرور ما دانلود نمیشه** — وقتی فایل از
   ربات مقصد می‌رسه، مستقیم (همون پیام) به ربات اول فرستاده میشه؛
   Telethon خودش فایل رو سمت سرورهای تلگرام کپی می‌کنه، بدون دانلود و
   آپلود دوباره. این هم سریع‌تره هم فضای دیسک/پهنای باند سرور رو اشغال
   نمی‌کنه.
   بعد از گرفتن فایل، **همون کپشنی که خود پست کانال مبدا داشت** رو
   برمی‌داره، دقیقاً همون مسیر دستی رو طی می‌کنه (ربات اول → لینک →
   ربات دوم → لینک نهایی) و با همون کپشن — بعد از هایپرلینک کردن کلمه‌ی
   تریگر با لینک نهایی، و جایگزینیِ برچسبِ آیدیِ کانال ته پیام (چه
   literal «ایدی کانال» باشه چه، مثل اکثر پست‌های کانال مبدا، آخرین
   `@یوزرنیم`ِ توی متن که برچسبِ خودِ کانال مبداست) با آیدیِ کانال
   مقصدمون — خودش پست رو توی همه‌ی کانال‌های مقصدِ **فعال** می‌ذاره —
   بدون نیاز به دخالت دستی و بدون اینکه چیزی ازت بپرسه که به کدوم کانال
   ارسال بشه.
3. اگه پست کانال مبدا کپشن نداشت، به‌جاش از «قالب جایگزین» (تنظیم‌شده از
   پنل) استفاده میشه؛ اگه اونم خالی بود، لینک نهایی برای ادمین‌ها فرستاده
   میشه تا دستی پست کنن.
4. «تعداد پست روزانه» تعداد فایل در ۲۴ ساعت رو محدود می‌کنه.
5. اگه کانال مقصد فعالی وجود نداشته باشه یا ارسال با خطا مواجه بشه، ربات
   به‌جاش برای همه‌ی ادمین‌ها پیام می‌ده (شامل لینک نهایی) تا دستی پست کنن.
6. حالت دستی (فرستادن فایل مستقیم به ربات و بعد کپشن با کلمه‌ی تریگر)
   دست‌نخورده باقی مونده و همچنان کار می‌کنه، با این تفاوت که دیگه
   نمی‌پرسه به کدوم کانال ارسال بشه — خودکار به همه‌ی کانال‌های مقصد
   فعال پست می‌کنه.
7. **زنجیره‌ی یک یا دو رباتی**: بعضی سیستم‌ها با باز کردن دیپ‌لینکِ زیر پست
   کانال مبدا، مستقیم گیت عضویت رو نشون میدن؛ بعضی دیگه به‌جاش یه دیپ‌لینک
   *دومی* برمی‌گردونن (همون ربات با پارامتر دیگه، یا یه ربات کاملاً جدا) که
   تازه اونجا گیت عضویت واقعی و فایل میاد. کد هر دو حالت رو پشتیبانی
   می‌کنه: تا ۶ مرحله دنبال لینک‌های زنجیره‌ای می‌گرده (چه توی متن پیام، چه
   روی دکمه‌های url‌دار)، و توی هر مرحله هم تا ۱۰ بار برای حل گیت عضویت
   تلاش می‌کنه (کافیه برای گیت‌هایی که ۵-۷ تا کانال/گروه همزمان می‌خوان).
8. **محدودیت دیپ‌لینک**: فقط فرمت `t.me/username?start=param` تشخیص داده
   میشه. اگه زنجیره بیش از ۶ مرحله طول بکشه، یا گیت عضویت با روشی غیر از
   دکمه‌ی url/کال‌بک کار کنه، ممکنه فایل گرفته نشه؛ توی این حالت یه پیام
   (شامل خود لینک) به همه‌ی ادمین‌ها میده تا دستی پیگیری کنن، و همون پیام
   رو یه‌بار‌مصرف حساب می‌کنه (دوباره خودکار امتحانش نمی‌کنه).

## بکاپ و بازیابی
از پنل اصلی دو دکمه هست:
- **📦 دریافت فایل بکاپ**: یه فایل JSON شامل همه‌ی تنظیمات، ادمین‌ها،
  کانال‌های مبدا/مقصد (با وضعیت فعال/غیرفعال)، Session String، و تاریخچه‌ی
  فایل‌های قبلاً پردازش‌شده (برای جلوگیری از پست تکراری) میسازه و همونجا
  توی همون چت خصوصی برات می‌فرسته.
- **📥 بازیابی از فایل بکاپ**: بعد از زدنش، همون فایل JSON رو (به‌عنوان
  فایل، نه متن) بفرست؛ همه‌چیز — تنظیمات، ادمین‌ها، کانال‌ها، و سشن —
  جایگزین میشه و اگه Session String توی بکاپ بود، سشن هم خودکار دوباره
  وصل میشه.

⚠️ **این فایل حساسه**: چون Session String توش هست، معادل دسترسی کامل به
اکانت سشنه. فقط جایی نگهش‌دار که خودت بهش دسترسی داری (نه توی یه چت گروهی
یا جایی که بقیه هم می‌بینن).

کاربرد اصلی: هر وقت تنظیماتت رو کامل کردی (یا تغییر مهمی دادی)، یه بکاپ
بگیر و جایی امن نگه‌دار؛ اگه یه روز مجبور شدی ربات رو از صفر روی یه سرور
دیگه/دیتابیس خالی بالا بیاری، به‌جای تنظیم دستیِ همه‌چیز از اول، همون فایل
بکاپ رو بهش بده تا همه‌چیز برگرده سرجاش.

- **آیدی عددی خام کانال مبدا/مقصد**: چون سشن با Session String (نه فایل
  سشن) کار میکنه، هر بار که پروسه ری‌استارت میشه، کشِ Telethon از
  موجودیت‌ها (کانال‌ها/چت‌ها) از صفر شروع میشه. برای همین، بعد از هر
  اتصال/لاگین، خودکار یه بار `get_dialogs` می‌زنیم تا این کش دوباره ساخته
  بشه. با این حال، اگه یه کانال مبدا/مقصد رو با **آیدی عددی خام** (نه
  یوزرنیم `@channel` یا لینک) اضافه کرده باشی، این فقط وقتی درست کار
  می‌کنه که اکانت سشن واقعاً از قبل عضو اون کانال بوده باشه (چون برای
  آیدی خام راهی برای «جوین شدن» نیست، فقط می‌تونیم موجودیتی که قبلاً
  دیده شده رو پیدا کنیم). اگه با خطای
  `Could not find the input entity` مواجه شدی، بهترین راه‌حل اینه که
  به‌جای آیدی عددی، از یوزرنیم یا لینک دعوت همون کانال استفاده کنی.

## نکته مهم
- **پست نهایی توی کانال‌های مقصد همیشه با اکانت سشن (یوزربات) فرستاده میشه، نه
  ربات اصلی (BotFather).** پس اونی که باید عضو/ادمین کانال‌های مقصد باشه
  اکانت سشنه، نه ربات. ربات اصلی هیچوقت پیام توی هیچ کانالی نمیذاره و لازم
  نیست عضو هیچ کانال مقصد/مبدا یا ربات اول/دومی باشه؛ فقط توی چت خصوصی با
  ادمین‌ها کار میکنه (پنل تنظیمات + گرفتن فایل).
- اکانت سشن (یوزربات) باید از قبل توی هر دو ربات (اول و دوم) استارت زده
  باشه و اگه ربات دوم نیاز به دسترسی خاصی (مثل ادمین بودن یا عضویت) داره
  از قبل ردیف باشه.
- تعامل با ربات دوم کاملاً بر اساس **موقعیت دکمه‌ها** انجام میشه، نه متنشون:
  هر بار اول `/start` بعد `/admin` فرستاده میشه، بعد کلید «آپلود فایل» (ردیف
  دوم، کلید دوم)، بعد کلید «تکی» (ردیف اول، کلید اول سمت چپ)، و در آخر بعد از
  گرفتن لینک نهایی، کلید «بازگشت» (تک دکمه‌ست، ردیف اول/کلید اول) هم کلیک
  میشه. اگه چیدمان کیبورد ربات دوم فرق داره، مقادیر `i` و `j` رو توی تابع
  `get_link_from_bot2` داخل `bot.py` عوض کن.
- **اعتبارسنجی ورودی**: «فاصله زمانی بین هر پست» و «تعداد پست روزانه» فقط
  عدد صحیح مثبت قبول میکنن؛ ورودی نامعتبر رد میشه و دوباره ازت میخواد.
- **مدیریت محدودیت فلود تلگرام (FloodWait)**: اگه تلگرام بگه باید صبر کنیم
  (روی ارسال پست، جوین شدن، یا گفتگو با ربات اول/دوم)، اگه مدت صبر کوتاه
  باشه (تا ۵ دقیقه) ربات خودش صبر میکنه و دوباره امتحان میکنه؛ اگه بیشتر
  باشه، به همه‌ی ادمین‌ها خبر میده و همون عملیات رو فعلاً رد میکنه (باید
  خودت بعداً دوباره امتحان کنی).
- **توقف کلی ارسال خودکار**: از پنل، دکمه‌ی «⏸ توقف ارسال خودکار» کل
  مانیتور کردن کانال‌های مبدا و پست خودکار رو موقتاً غیرفعال میکنه، بدون
  اینکه چیزی حذف بشه؛ با دکمه‌ی «▶️ فعال‌سازی» دوباره روشن میشه. حالت
  دستی (فرستادن فایل مستقیم) تحت تاثیر این سوییچ نیست و همیشه کار میکنه.
- **هشدار قطع شدن سشن**: اگه اکانت سشن قطع بشه یا دیگه معتبر نباشه (مثلاً
  لاگ‌اوت شده یا محدود شده)، ربات یه بار به همه‌ی ادمین‌ها پیام میده که
  دوباره لاگین کنن؛ وقتی سشن دوباره وصل بشه، یه پیام تاییدیه هم میفرسته و
  ارسال خودکار از سر گرفته میشه.
